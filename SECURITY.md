# Security policy

## Supported versions

Security fixes are applied to the latest tagged minor release. Pre-release and
unreleased research branches are not supported.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue. Use GitHub's
private vulnerability reporting feature after the repository is published. If
that feature is unavailable, contact the repository owner using the address on
their GitHub profile.

Include the affected version, platform, reproduction steps, impact, and any
known workaround. Allow time for assessment before public disclosure.

## Scientific-result integrity

Incorrect numerical results are usually scientific software defects rather
than security vulnerabilities. Report reproducible errors, silent NaNs,
incorrect boundary enforcement, and misleading outputs through the normal issue
tracker unless they can be exploited to compromise a system or confidential
data.
